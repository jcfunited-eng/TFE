# Embodiment

Embodiment is part of everything. A construction that exists only as a
backtest JSON is a claim, not a fact — this project's core disaster
(the +503-630% mirage) was a bench victory mistaken for a body. The
doctrine, ratified in practice across this campaign:

## The ladder every result must climb
1. **Research replay** — strict honest-timing measurement
   (tfe-honest-timing), filed with misses.
2. **Cross-rung replication** — the same construction blind on
   independent data. Selection dies here or earns the next rung.
3. **Live embodiment (paper)** — wired into a channel that runs on
   real closes, real feeds, real clock, with a PUBLIC page and a
   DECLARED expectation stated before the first pass. Divergence from
   the declaration is information, not embarrassment. This is where
   herd_kgate_v1 lives now.
4. **Real orders** — only on Joe's explicit word, never assumed.
5. **Horizon**: the physics ultimately embodies in hardware (the
   physical-substrate goal the whole program funds). Every layer of
   flattening between the spec's field and running code is debt
   against that horizon — record any such compromise explicitly.

## What embodiment demands of engineering
- The live engine must BE the measured construction — same ids, same
  ledgers, same constants; parity-tested before wiring. If the live
  implementation drifts from the research one, the measurement is void.
- Determinism: identical inputs -> identical decisions, twice, always.
- The body must survive its world: restart-safe state on disk,
  self-healing wakeups, full-history replay so a dead process loses
  nothing but time.
- Honest instrumentation: the page describes what the engine actually
  does, in plain language, including its expected scale. No trophy
  dashboards.

## The test of any proposal
Ask: "what does this look like running at 21:10 tonight, and what
number on which page will prove it wrong?" If there is no answer, it
is not yet real work — it is a bench.
