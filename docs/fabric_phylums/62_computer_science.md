# 62 COMPUTER SCIENCE — what computing is, beneath any machine

ESSENCE: an algorithm is a recipe independent of its cook — the
  same steps give the same answer on paper, silicon, or brass
  gears; the steps are the thing, the machine a stage.
ROOT: development methods / known acts in order; mathematics /
  truths do not depend on who counts.
CANNOT: no answer owned by the machine — if two runs of the same
  steps on one input disagree, one ran different steps.
THREAD: cooking (the recipe, exactly), music (one score, any
  instrument), law (a procedure is valid whoever the clerk).
ASKED-AS: algorithm what is recipe steps computer method same answer any machine calculation rules

ESSENCE: how facts are arranged decides how fast they are found
  — a heap of papers and a labeled cabinet hold the same facts,
  and one hides them.
ROOT: craft / arrangement is work stored up in advance.
CANNOT: no arrangement best at everything — the cabinet quick to
  search is slow to toss into; every ordering is paid at the
  door.
THREAD: libraries (shelving IS the search), kitchens (everything
  chopped before the heat goes on), the body (memory found by
  association, not by date).
ASKED-AS: organize sort filing find fast lookup list order storage search arrangement messy

ESSENCE: cost grows with size in different shapes — some methods
  barely notice a million while others drown at a thousand; the
  shape of growth, not the speed of the machine, decides what is
  feasible.
ROOT: mathematics / doubling and redoubling outruns any steady
  climb.
CANNOT: no buying out of a bad shape — a machine ten times
  faster moves the wall one size along, never removes it.
THREAD: money (compound interest, the same shape as ruin),
  crowds (handshakes grow as pairs, not persons), farming (weeds
  double; rows only add).
ASKED-AS: slow big scale huge takes forever faster computer efficiency size million exponential

ESSENCE: a system is its current state plus rules for moving —
  where each event sends it next; traffic lights, door locks,
  and spell-checkers are all this one thing.
ROOT: causation / the next moment is written from this one.
CANNOT: no move without a rule, and no memory outside the state
  — its past survives only as where it stands now, or not at
  all.
THREAD: board games (the position is the whole game), law
  (married, licensed, expired — moved by defined events), music
  (which chord may come next).
ASKED-AS: state mode status rules next transitions machine current position changes remembers step

ESSENCE: each layer keeps its promises and hides its workings so
  the layer above can think simply — the driver needs the
  pedal's promise, not the pistons.
ROOT: craft / a tool is used by its handle, not its insides.
CANNOT: no thinking simply above a broken promise — a leaking
  layer forces those above to know what they were built to
  ignore.
THREAD: money (a banknote hides the vault), the body (you
  command the hand, not the fibers), restaurants (menu above,
  kitchen below).
ASKED-AS: layers hidden underneath interface hood details simple on top levels stack inside promise

ESSENCE: any computer can imitate any other, given time and
  memory — computation is one thing wearing many bodies, and a
  new body adds speed, never answers.
ROOT: this file / the recipe is independent of its cook.
CANNOT: no special machine with private answers — nothing
  computable on one and impossible on another; machines differ
  in fast, never in deep.
THREAD: music (any melody on any instrument), games (chess is
  chess on wood, marble, or memory), language (one story, many
  tongues).
ASKED-AS: emulate imitate simulate universal any computer same power old games phone runs everything

ESSENCE: no program can decide, for every program, whether it
  finishes — proven, not merely unsolved; some questions are
  dead to all machines forever.
ROOT: logic / a rule turned on itself can be built to defeat
  itself.
CANNOT: no all-seeing checker — hand it a program built to do
  the opposite of whatever it predicts, and it is wrong by
  construction. Not unlikely: dead.
THREAD: prophecy (a prediction its subject hears can be defied),
  mathematics (the same self-reference wall Gödel found), the
  fabric's first law (permanent gaps are named, not filled).
ASKED-AS: impossible unsolvable halting problem cannot compute limits forever infinite loop know if ends

ESSENCE: a message carries information only where it could have
  been otherwise — the predictable part weighs nothing; "the sun
  rose" tells less than "the mail came early".
ROOT: chance / the rarer the outcome, the more its report tells.
CANNOT: no information from certainty — the already-sure message
  carries zero at any length; no squeezing a message below its
  surprise without loss.
THREAD: money (UNSURE — prices said to move only on surprise,
  the expected already paid for), conversation (the bore repeats
  the known), music (all-predictable is a drone, all-surprise is
  noise).
ASKED-AS: information surprise news bits compression zip predictable boring nothing new message data

ESSENCE: enough redundancy lets a message survive damage — say
  it three ways and one wound leaves two witnesses; certainty
  rebuilt from majority votes.
ROOT: evidence / one witness is a story, two are a fact — built
  into the message itself.
CANNOT: no protection for free — every guard-copy costs extra
  length; no majority survives damage bigger than itself.
THREAD: the body (two kidneys, spare copies in every cell), law
  (deeds in triplicate), speech (language padded so a noisy room
  cannot kill the sentence).
ASKED-AS: scratched cd still plays typo readable correction backup copies noise static garbled survives

ESSENCE: keeping an answer costs space, re-deriving it costs
  time — every system trades one for the other.
ROOT: craft / work stored up in advance — the kept answer is its
  purest case.
CANNOT: no having both for free — never store and you repeat;
  store all and you must house and search it. And no trusting a
  kept answer whose question has changed.
THREAD: cooking (a freezer of meals vs fresh), the mind
  (times tables vs counting on fingers), money (warehouse stock
  vs made to order).
ASKED-AS: cache save answer recalculate lookup table memorize faster space time tradeoff stale memory

ESSENCE: many hands are faster only when the work truly splits —
  and two hands on one value produce a fight nobody wins, each
  undoing the other's half-done work.
ROOT: craft / division of labor; causation / two causes on one
  effect need an ordering.
CANNOT: no speedup past the unsplittable part — nine diggers do
  not dig one posthole nine times faster; no safe sharing
  without turns.
THREAD: kitchens (eight cooks, one pan — the pan is the limit),
  money (two clerks on one ledger line), farming (rows split;
  the one gate does not).
ASKED-AS: parallel multitask cores threads same time faster together conflict overwrite race shared
