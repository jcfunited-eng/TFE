# 61 SOFTWARE DEVELOPMENT — how programs are made and kept alive

ESSENCE: a program is instructions for a perfectly obedient,
  perfectly literal servant — tireless, fast, without a drop of
  common sense; it does exactly what was said, never what was
  meant.
ROOT: development methods / a procedure is known acts in order;
  language / words do not carry intent by themselves.
THREAD: law (a contract binds by its letter), genies (every
  wish-gone-wrong story is this law), cooking (a recipe followed
  by someone who has never seen food).
ASKED-AS: computer program code instructions literal exact what is coding software machine obeys commands

ESSENCE: a bug is the distance between intent and instruction —
  the machine executed faithfully; the fault lives in the
  writing.
ROOT: this file / the servant is perfectly literal.
THREAD: music (the orchestra plays the wrong note as printed),
  law (a drafting error enforced to the letter), teaching (the
  student who did exactly what the worksheet said).
ASKED-AS: bug glitch broken error crash wrong fault mistake fix why computer program

ESSENCE: what is wanted must be stated before what is built can
  be judged — a program is only right or wrong against a stated
  want; unstated wants are unbuildable.
ROOT: law / no verdict without a standard to judge against.
THREAD: building (blueprints before ground is broken), cooking
  (no cooking "something nice" for a stranger), teaching (the
  test must exist before grading can be fair).
ASKED-AS: requirements spec specification what do you want needs plan before building software project

ESSENCE: a working program is many small parts with one job each
  — a part that does two jobs breaks two ways, and hides which
  way it broke.
ROOT: development methods / any doable task breaks into smaller
  acts; craft / one tool, one purpose.
THREAD: the body (one heart, one job), kitchens (a knife that is
  also a spoon is bad at both), music (each instrument holds its
  own line).
ASKED-AS: parts pieces modules functions split small simple one thing each organize messy code

ESSENCE: a passing test proves the presence of one behavior,
  never the absence of all faults — tests are lanterns in a dark
  house; each lights one room.
ROOT: evidence / searching can find what is there, never certify
  that nothing is anywhere.
THREAD: medicine (a clear scan clears only what it scanned), law
  (acquitted is not proven innocent), cooking (one taste is not
  every spoonful).
ASKED-AS: test testing passed works checked proof no bugs safe sure quality trying it

ESSENCE: to find a fault, cut the suspect ground in half and ask
  which half holds it — repeated halving shrinks any haystack to
  a straw; the fault cannot hide from a shrinking search.
ROOT: mathematics / halving reaches one from any number in few
  steps.
THREAD: medicine (drop half the diet, see if the rash stays),
  electricity (test a dead wire at its midpoint), everyday loss
  (retrace by halves, not by luck).
ASKED-AS: find bug where broken narrow down half search isolate which part cause locate debugging

ESSENCE: every change is kept with its history, so any mistake
  can be walked back — work without history is work on a
  tightrope, where one slip is the whole act.
ROOT: writing / memory outside the head survives the head.
THREAD: law (amendments keep the crossed-out text), games (the
  saved game that makes daring play possible), families (the
  album that says who we were).
ASKED-AS: undo save versions history backup old copy restore go back track changes before

ESSENCE: a program stands on other programs written by strangers
  — and what it stands on can shift under it while its own text
  never changed a letter.
ROOT: building / every structure rests on ground it did not
  make.
THREAD: money (a shop leans on its suppliers' suppliers),
  farming (the crop stands on soil and seed it did not make),
  the body (fed by gut microbes it never chose).
ASKED-AS: libraries depends update broke suddenly stopped working nothing changed install other software pieces

ESSENCE: code is writing for humans first — the machine reads
  anything, however tangled; the next person must understand it
  or the program dies with its author.
ROOT: writing / memory outside the head survives the head.
THREAD: music (notation lets a score outlive its composer),
  cooking (the recipe card a granddaughter can follow), law
  (statutes rule long only by being readable).
ASKED-AS: readable clean code comments understand messy confusing naming clear maintain other people

ESSENCE: a wrong choice is cheap today and ruinous after
  everything is built on it — the cost of change grows with all
  that has come to lean on the thing changed.
ROOT: building / foundation then walls; what is under carries
  what is over.
THREAD: cities (the street grid outlives every building on it),
  law (constitutions amend harder than by-laws), farming (the
  orchard planted in the wrong field).
ASKED-AS: too late rewrite start over stuck foundation early decision expensive legacy old system change

ESSENCE: every added piece must pay rent — earn its keep in work
  done — because complexity compounds like debt: each new piece
  must be understood beside all the others, forever.
ROOT: this file, composed / parts, dependencies, readability,
  and the growing cost of change.
THREAD: money (debt compounding), farming (every animal kept
  must be fed all winter), packing (everything carried is
  carried the whole way).
ASKED-AS: simple complicated bloated features too many keep small less is more clutter minimal
