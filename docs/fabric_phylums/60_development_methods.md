# 60 DEVELOPMENT METHODS — how procedures come to exist

ESSENCE: any doable task breaks into smaller acts until every act
  is one already known; the breaking IS the design. A task that
  cannot be broken down to known acts is not yet doable — and the
  break-point names exactly what knowledge is missing.
ROOT: craft / all making is arranging known moves.
CANNOT: no procedure runs on acts nobody possesses. No amount of
  cleverness at the top substitutes for a missing act at the
  bottom.
THREAD: cooking (recipes are this law written down), teaching
  (lessons break skills the same way), the machine's own doing.
ASKED-AS: steps plan procedure recipe break down task how to method instructions program

ESSENCE: order is part of the procedure — the same steps in a
  different order are a different procedure, usually a wrong one.
ROOT: causation / effects follow their causes.
CANNOT: no checking work before the work exists; no carrying a
  ten before the column that produced it is counted.
THREAD: cooking (bake then frost), building (foundation then
  walls), law (verdict after evidence).
ASKED-AS: order sequence first then before after steps wrong backwards out of order

ESSENCE: repetition needs a stopping test — do the step, ask "am
  I done", and the asking must someday answer yes.
ROOT: mathematics / counting — every loop is a countdown in
  disguise.
CANNOT: no honest procedure repeats without a reachable end. A
  loop with no stopping test is not patience, it is a trap.
THREAD: farming (till until the row ends), music (repeat signs
  carry counts), computing (every program hang is this cannot
  ignored).
ASKED-AS: repeat loop until done again keep going stop finished when end

ESSENCE: a result is trusted only when a second, different route
  agrees — an estimate, a reverse walk, a recount by another
  hand.
ROOT: evidence / one witness is a story, two are a fact.
CANNOT: no procedure certifies itself by running once. The same
  route rerun repeats its own blindness.
THREAD: money (books balance two ways), carpentry (measure
  twice), the machine's checking of its own answers.
ASKED-AS: check verify double check estimate confirm mistake error catch wrong answer

ESSENCE: when no known act fits a step, the honest output is the
  NAME of the missing act — not a guess dressed as an answer.
ROOT: the fabric's own first law — never pretend.
CANNOT: no filling a knowledge gap with confidence. A named gap
  can be bought; a hidden one poisons everything downstream.
THREAD: medicine (differential names what tests are missing),
  teaching (the student who names confusion learns), this
  machine's refusals.
ASKED-AS: missing unknown gap cannot stuck need dont know what is needed name it

ESSENCE: a procedure once assembled and checked is written down
  and kept — created procedures are knowledge like any other
  entry, with their parentage stated.
ROOT: writing / memory outside the head survives the head.
CANNOT: no re-deriving from scratch what was already derived and
  filed — that is the cost of not writing it down, paid every
  time.
THREAD: law (precedent), cooking (the family recipe card), this
  machine keeping the procedures it assembles.
ASKED-AS: save keep write down record reuse remember procedure file next time
