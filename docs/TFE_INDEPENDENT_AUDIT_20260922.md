## Findings

**1. CH2 is not the requested lifetime assessment, but the claim that C_k never reaches L5 is wrong for current source.** `web/scripts/execution/ch2_strategist.mjs:119` explicitly passes all nine named values, including C_k, to `v3_basin.mjs:22`; missing values refuse the candidate. `uf_core/uf_structural_engine.py:279` omits C_k from the six-entry compatibility vector but preserves it explicitly at line 314. The wrapper receives closes and invokes the kernel chain at lines 241–249. It also constructs S_UF/R_UF aggregates at lines 259–260. Their equivalence to the requested authoritative stability must be established, not assumed. CH2 evaluates the latest snapshot and adds `B_k > -0.50` and basin cutoffs; this does not establish joint lifetime governance. A deterministic threshold is not, by itself, a physical derivation. Do not change the frozen kernel to repair this boundary.

**2. CH6 uses another kernel realization and a reduced selection mechanism.** `tools/ch_entry_reading.py:66` imports `ch4_uf_kernel_v2`, whose header claims side-channel-only usage and documents changed L0–L4 realizations. That header is contradicted by its caller. Its claimed historical authorization was not independently established. Whole-history computation does run, but the resulting phase summaries are largely filed rather than used as selection authority. `ch6_pool.py:94` admits using extinction, URF and stability decline, omitting the full joint tuple. `ch6_stage_slate.py:77` assigns every pool candidate confidence 0.5, sorts by confidence, and checks only the first `target * 3` candidates. Since the pool is constructed alphabetically, equal-confidence selection under capital limits inherits alphabetical order. Existing reading directories can also reactivate reading-based selection despite comments saying it is off.

**3. CH2's structural exit supplier is disabled.** `tools/ch6_nightly_door.sh:36` disables the model-based holdings pass. The sentinel still consumes DRIVE_DYING/DEAD sheets, while missing/stale sheets hold. Thus these structural exits lose their supplier; dead-clock, age and price protections are not equivalent replacements. This supports the user's concern about missing structural harvesting. Re-enabling per-ticker model sessions would not meet deterministic governance or the token constraint.

**4. Massive refresh can conceal incomplete raw input.** `tools/ch4_store_refresh.py:65` converts fetch exceptions into empty results, then reports “already current” when no rows arrive. If later dates succeed, future runs start after the global maximum date and never revisit the earlier missing day. The 1.8× seam rule deletes the entire ticker history from the store, conflating genuine displacement with adjustment mismatch. Direct parquet replacement is not atomic. `ch4_spring_daily_runner.sh` continues downstream after failures because its command group has no failure gates. These can invalidate field assessment before L5 begins.

**5. Freshness protection is incomplete.** CH2's four-day guard uses publication timestamp, not each ticker's last completed source bar (`ch2_strategist.mjs:66`). Rebuilding old inputs can therefore satisfy that guard. Local CH6 book last update: September 18, 23:03 UTC; local store mtime: September 18, 21:13 UTC; runner heartbeat files stop September 21, 02:23 UTC. These establish stale local evidence, not a proven production outage. CH6 also hardcodes 13:30 UTC session opening and 19:55 UTC sweep (`ch6_fast_harvest.py:634`, `ch6_loop.sh`), which do not follow daylight-saving changes or early closes.

**6. “Tivali” was not found; Tavily is present.** Tavily search text and generated answers are concatenated and first matching numeric patterns become fundamentals (`tools/tavily_fundamental_fetcher.py:97`). Extraction does not bind each number to a reporting period or issuer-specific source. Worse, `backfill_accumulate_fundamentals.py:557` can write a hardcoded `claude_fundamental_fallback.py` table into normalized fundamentals. It includes market capitalizations labelled April 2026. CH2's admission reads market cap from runtime symbols or this fundamentals table. Current production exposure is unverified; the executable fallback exists. These values must not be treated as freshly verified provider data.

**7. Broker execution and local simulation are different evidence.** CH2's sentinel calls the Alpaca bridge, which requires paper mode (`alpaca_bridge.mjs:118`). CH6 fills its local JSON book from observed trade prints, without placing an Alpaca order in that fill path (`ch6_fast_harvest.py:723`). CH6 deducts liquidity-bucket estimates for carry and slippage (`ch_desk.py:12`), not actual broker charges. Its +2% sweep, +5% trailing activation/one-point giveback, day-five backstop and -20% trigger exist, but target prices are not guaranteed fills. Even Alpaca paper trading omits execution effects; see [Alpaca paper documentation](https://docs.alpaca.markets/us/v1.4.2/docs/paper-trading).
