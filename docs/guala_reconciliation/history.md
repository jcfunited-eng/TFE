## Lessons that must survive the reconciliation

| Repeated failure | Durable correction |
|---|---|
| A term survives while its mechanism changes. | Bind every capability name to an actual state transition, source version and evidence level. |
| A document declares itself canonical or complete. | Trace direct approval separately from source, test, package and production proof. |
| A module exists but is not called. | Prove ordinary startup, active caller, consequence and sensory return. |
| Identity survives while cognition is replaced. | Prove retained-state and next-transition continuity, not only UUID/tick equality. |
| A result looks successful because a test supplies the answer. | Use actual experiences, retained change, partial cues, causal ablation and cold continuation. |
| Passing tests repeatedly widen computational admission. | Keep the original failure and derive an execution envelope from necessary physical work. |
| A performance repair changes cognition or drops history. | Prove the same physical successor and preservation; do not trade truth for cadence. |
| Multiple trees/packages use the same architecture name. | Record ancestry, copied source, manifest, loaded binary and live body separately. |
| “Whole brain” becomes a poll of every component. | Preserve connected responsibilities while advancing only the reached causal frontier. |
| Historical documents disappear from the active checkout. | Keep a small canonical entry point, preserved sources and a complete revision index; do not rewrite the past to match today's claim. |

Open approval, checkpoint, lineage-transfer and original-witness gaps are
listed in [evidence](evidence.md). They remain explicit work, not assumed
successes or an excuse to discard recovered mechanisms.
