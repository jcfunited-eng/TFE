# ArcLoom foundations, MathLoom and experience-first reconciliation

This is a source-bound historical reconciliation, not a system certificate. It covers14 documentary byte versions across11paths and9 current implementation files. Eleven documentary versions were read in full; the other three master versions were reconciled through every complete chronological delta from the fully read base. All9 captured implementation files were read in full. This does not clear their entire revision history, transitive callers, loaded FPGA configuration or production deployment.

January-dated foundation documents first occur in the recovered April22 history. The processor/master specifications enter April10; the master gains familiarity on May3 and a later same-day validation claim. Experience-first v1/v2 are recovered together on July2, with v1 explicitly retrofiled after overwrite. A date printed in a document is not proof of execution or original approval.

The valid improvements include explicit experience context and accountability, honest failure reporting, exact native numeric representation, and current HDL comments that disclose ripple/clocked arithmetic. Rejected mechanisms include authored familiarity/target-score motor control, reduced-field authority, counter-based certainty and unsupported physical/performance claims. Missing evidence remains a gap, not proof of misconduct.

Ten [exact mathematical counterexamples](historical-equation-falsifiers.json) falsify specific printed claims. Their [reproducer](sources/arcloom-history/historical_equation_falsifiers.py) uses exact arithmetic and imports no organism. Passing that diagnostic means the historical claim failed; it does not mean the product passed. The [structured record](arcloom-history-reconciliation.json) carries hashes, original Git blobs, exact anchors and action mappings.
