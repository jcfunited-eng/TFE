## Reconciled dependency direction

The original authorized requirement determines the specification. The
specification defines the allowed causal design and retained state. Implementation
must have an exact relation to that design. Unit, module and system evidence
test its particular claims, and release/live custody establishes what actually
runs. Skills and the UI describe those same boundaries. They do not create an
alternative architecture through convenient terminology.

A failed test can expose a specification defect or missing operator. It must
not silently rewrite the requirement. A later successful report cannot make
a previously unmounted path retroactively live. A documented historical
proposal may remain valuable evidence even when it was never approved or built.

## Concrete lifecycle evidence to retain

For each repaired mechanism, one trace must connect the governing clause and
decision, causal design, complete persistent state, source and callers, unit
invariant, module transmission, system experience/use/continuity, resource
measurements and immutable release/live result. The trace must also name removed
authority, remaining unsupported behavior and the exact scope of any test.
This is the existing mechanism contract applied consistently, not a second
status ledger or a new checklist that substitutes for physics.

The [coverage record](coverage.md) identifies what has actually been reviewed.
The complete recovered index remains available for continuing every remaining
family and version; none is silently marked reconciled because it was copied.
