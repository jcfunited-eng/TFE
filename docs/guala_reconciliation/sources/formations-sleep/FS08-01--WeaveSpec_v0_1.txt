1. What a Weave Is
------------------
A Weave is the ArcLoom equivalent of an app. It specifies how the loom couples to inputs, how it constrains internal settling (laws/goals), what it commits to memory, and how it renders outputs. A weave is mounted, not executed.

2. How a Person Uses Weaves
---------------------------

You do not need to write code to use a weave.

How to use (plain steps):
1) Pick a weave (example: “Text Weave”).
2) Mount it (turn it on). The loom starts listening to inputs.
3) Interact normally (type/speak/move/gesture). The loom forms episodes (gates) and commits stable motifs.
4) The weave renders outputs (text/audio/graphics/actions) while staying bounded and safe.
5) Unmount it (turn it off) when done.
6) Export or share only if you choose (privacy controls apply).

What you will see:
• A “Now” panel: current DSF summary and stability status (Safe / Hold / SafeMode).
• A “History” panel: committed strands (what became stable history).
• A “Motifs” panel: reusable chunks the weave learned/used.

If the system shows “SafeMode”:
• It will stop taking outward actions and hold outputs.
• You can keep interacting; it will resume after recovery.


3. Lifecycle
------------
Defines the deterministic lifecycle of a weave from authoring to mounting to committing motifs.

3.1 Lifecycle states
--------------------

Lifecycle states (normative):
• AUTHORED: WeaveSpec exists.
• VALIDATED: schema + bounds + UF/ArcLoom compatibility checks pass.
• MOUNTED: couplers active; governance active.
• RUNNING: UF emits DSF per gate; ArcLoom evolves ψ; outputs rendered.
• COMMITTING: determinism thresholds met; strands committed to memory.
• UNMOUNTED: couplers inactive; memory persisted.

A weave MUST be VALIDATED before it can be MOUNTED.


4. JSON structure
-----------------
Defines the canonical WeaveSpec JSON format and required fields.

4.1 Schema
----------

Top-level object (required fields marked *):
{
  "weave_id": "string*", 
  "version": "0.1*",
  "title": "string*",
  "description": "string",
  "authors": ["string"],
  "created_utc": "YYYY-MM-DDTHH:MM:SSZ*",

  "couplers": { ... }*,
  "uf_profile": { ... }*,
  "arcloom_profile": { ... }*,

  "laws": [ ... ]*,
  "goals": [ ... ],
  "memory_policy": { ... }*,
  "commit_policy": { ... }*,
  "governance": { ... }*,

  "interop": { ... }   // optional: BSIL hooks
}

Canonicalization:
• JSON must be UTF‑8.
• Keys are sorted lexicographically for hashing.
• Numeric fields must declare precision (e.g., "float32" or "float64") and clamp bounds.


5. Determinism
--------------
Ensures a weave is deterministic and auditable.

5.1 Determinism rules
---------------------

Determinism rules (normative):
• If any randomized procedure exists, it MUST be driven by an explicit seed in WeaveSpec.
• Tie-breaks MUST be specified (e.g., “lowest id wins”).
• Precision MUST be specified (float32/float64) and used consistently.
• All outputs MUST be bounded and SafeHold behavior must be explicit.

Recommended option (and v0.1 locked): 
Use float64 for UF/ArcLoom core calculations in reference implementations, and record hashes for replay.


6 Laws and goals
----------------
Defines the declaration of Law-Fields and Goals as selectable constraint bundles.

6.1 Law/Goal examples
---------------------

Law entry (example):
{
  "law_id": "symmetry.basic",
  "weight": 0.25,
  "family": "symmetry",
  "params": { "type": "mirror", "axes": ["x"] },
  "bounds": { "max_norm": 1.0 }
}

Goal entry (example):
{
  "goal_id": "text.coherence",
  "weight": 0.40,
  "family": "coherence",
  "params": { "style": "plain", "max_len": 2000 },
  "bounds": { "max_norm": 1.0 }
}


7 Couplers
----------
Defines input/output couplers for a weave. Couplers are the only ways a weave touches external reality.

7.1 Coupler schema
------------------

Example couplers:
"couplers": {
  "inputs": [
    {"id":"mic", "type":"audio", "sample_rate":16000, "schema":"pcm16"},
    {"id":"kbd", "type":"text",  "schema":"utf8"},
    {"id":"cam", "type":"vision", "schema":"motion_vectors"}
  ],
  "outputs": [
    {"id":"screen", "type":"text_render", "max_rate_hz":30},
    {"id":"speaker","type":"audio_render","max_rate_hz":60}
  ]
}

Coupler rules (normative):
• Outputs MUST declare max_rate_hz and max_magnitude.
• Outputs MUST declare SafeHold behavior (usually “emit nothing”).


8 Memory/commit
---------------
Defines how the weave stores history and what counts as a commit.

8.1 Commit/memory examples
--------------------------

Commit policy (example):
"commit_policy": {
  "det_commit": 0.85,
  "p_commit": 0.70,
  "max_commits_per_min": 30,
  "cooldown_gates": 2
}

Memory policy (example):
"memory_policy": {
  "motif_budget": 5000,
  "strand_budget": 20000,
  "decay": {"half_life_days": 30},
  "landmarks": {"enabled": true, "max_landmarks": 200},
  "export": {"default": "private", "allow_share": false}
}


9 Governance
------------
Governance binds the weave to UF hardening and defines SafeMode/SafeHold behavior.

9.1 Governance example
----------------------

"governance": {
  "uf_hardening": "required",
  "safe_mode": {
    "freeze_commits": true,
    "freeze_memory_updates": true,
    "disable_outputs": true
  },
  "output_bounds": { "y_max": 1.0, "max_actions_per_min": 60 },
  "logging": { "trace_level": "full", "retain_days": 7 }
}
