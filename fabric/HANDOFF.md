# HANDOFF — read this, then DIRECTION.md, then FIRST_RIBBON.md

## Where it stands
5,368 pieces of knowledge in docs/fabric_phylums/, 4.6 MB of
plain text. Each is a claim plus what it rules out. They declare
49,519 links between themselves in their root and thread lines.

WORKS:
- core.py loads the whole thing in a second, indexed, bitwise.
- os_fabric.py routes a question along the declared links. This
  is the one real gain: bread, whip, sky and a figurative
  question all answered correctly, after failing all night by
  word matching.
- follower.py + interpreter.py run written procedures. Arithmetic
  comes from sentences in the knowledge, not from code: a new
  entry made it add in binary with no code change. Remove an act
  entry and the ability dies naming what it lacks.
- maker.py eliminates by law and reports both what stands and
  what closed.

DOES NOT WORK:
- No parsing. first_ribbon.py learns word classes from the
  corpus (that part works) but its grouping and nesting do not.
- No conversation. No world building. No thinking.
- Questions with an ambiguous word still land in the wrong
  subject (onions/cry -> mourning rites).

## The rules that were broken repeatedly — do not break them
1. Knowledge is the processor. Any decision in code is a defect.
   Every failure this session was a decision I put in code.
2. Plain speech to Joe. No invented vocabulary, no metaphor, no
   fenced theatre. He has corrected this more than ten times.
3. Never report a passing test as a working system. Ask: does it
   run when I am not typing?
4. Read the fabric's own walls before designing anything. They
   rule out routes and save nights.
